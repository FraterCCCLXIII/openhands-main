<h1>MiniMax M2.5: Open Weights Models Catch Up to Claude Sonnet</h1><p>For a long time, Claude has been the reigning leader in coding models. There have been few models that have been able to come close, although arguably OpenAI with its new model, GPT 5.3 Codex, is making a play for the throne as well.</p><p>And up until now, while great progress had been made on open models, there had not really been an open model that could come near the quality and versatility of the flagship models in the Claude Family, Sonnet and Opus. Today, I feel that we can say this has changed at least to some extent: with the new release of <a href="https://www.minimax.io/">MiniMax M2.5</a>, there is a model that I can impartially say is basically up to the quality of Claude Sonnet.</p><p>We got early access to the models, so read below for our testing and impressions, and also directions on a <strong>limited-time offer on using MiniMax-M2.5 free</strong> on the OpenHands Cloud.</p><h1>The Numbers</h1><p>We have recently released the OpenHands Index, a broad coverage benchmark that spans a variety of tasks in software engineering: issue resolution, greenfield app development, frontend development, software testing, and information gathering.</p><p>The reason why we created such a benchmark was because we wanted to know as soon as possible after a model release whether it was a model that was worth paying attention to across several axes: accuracy, cost, and issue resolution time (all of which are important to developers of course). You can see more details about it in on the <a href="https://index.openhands.dev/">OpenHands Index Site</a> or our <a href="https://openhands.dev/blog/openhands-index">blog</a> explaining the motivation further.</p><p>First, the most important numbers, the composite average over the index are shown below:</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="OpenHands Index composite benchmark scores showing MiniMax M2.5 in 4th place" src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/698d3ccbd8d04829eb479d8f_698d3ca4afc03468319cf8a3_Screenshot_2026-02-12_at_1.56.30_AM.png" loading="lazy"/></div></figure><p>MiniMax-M2.5 clocks in at 4th, behind only models in Claude’s premium Opus family, and OpenAI’s special purpose coding model GPT-5.2 Codex. It is also the first open model (indicated with a blue open lock) that has exceeded Claude Sonnet on my recent tests.</p><p>Looking at the cost-performance tradeoff, the model has significantly pushed up the frontier, it’s basically a two-horse race between Claude Opus on the most capable but pricy side, and M2.5 on the very inexpensive and still highly capable side. At a price point approximately 13x cheaper than Opus, it could open up a new set of use cases that were not possible otherwise.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="Cost vs performance chart comparing MiniMax M2.5 to Claude Opus" src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/698d3ccbd8d04829eb479d87_698d3cb40a8ffd3401e6ae7a_Screenshot_2026-02-12_at_1.58.39_AM.png" loading="lazy"/></div></figure><p>Looking more concretely at the task breakdown, M2.5 performed particularly well at long-running tasks of developing new apps from scratch, and had solid performance across all other categories. This capability has long been one where smaller models have struggled, so it is nice to see open models catching up here. It also was quite strong on issue resolution and software testing.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="Task breakdown scores for MiniMax M2.5 across different software engineering tasks" src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/698d3ccbd8d04829eb479d96_698d3cb330287d6e2aa5134e_Screenshot_2026-02-12_at_2.05.17_AM.png" loading="lazy"/></div></figure><p>In addition, looking at the model size, M2.5 is 230B parameters, with 10B active parameters, which is relatively small among the highly capable open models that we have evaluated. This means that it could also be locally deployed for those interested in doing so.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="Model size comparison chart showing M2.5 at 230B parameters with 10B active" src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/698d3ccbd8d04829eb479d99_698d3cb330287d6e2aa513b8_Screenshot_2026-02-12_at_2.02.47_AM.png" loading="lazy"/></div></figure><h1>Vibe Checks</h1><p>Of course, we can’t rely solely on benchmarks to see how well a model is doing, it is equally important to actually try out the model ourselves! So we put it through its paces. Typically open models have struggled with <strong>generalization</strong> — they were quite good at one-shot solving of bugs on repos, but less good at doing more complex things like interacting with APIs, etc. Here are some things we tried out:</p><ul role="list"><li>Checking the review on a pull request using the github API, fixing the review comments, and resolving them through the github API.</li><li>Filtering through all the pull requests open on a repo, and assigning them to the appropriate maintainer to review using git blame.</li><li>Finding out why a frontend app was not displaying properly and fixing the issues.</li></ul><p>and several others. Overall, the model proved quite capable, and all of the tasks we tried it managed to finish, although sometimes with a little back-and-forth. Very impressive!</p><p>That being said, we there were some issues. For instance, the model pushed to the wrong branch once, and also in one of our benchmarks it was instructed to add its answer between the solution tags “”, but occasionally it forgot, leading to a lower score on this information gathering task. So while a very strong model, there is still room to improve.</p><h1>Limited Time Free Usage of MiniMax M2.5</h1><p>As part of our early access to M2.5 for testing purposes, MiniMax has extended the opportunity for OpenHands users to access their model for <strong>free</strong> on the OpenHands cloud for a limited time.</p><p>To access M2.5, travel to the <a href="https://app.all-hands.dev/settings">OpenHands Cloud LLM Settings</a>, select OpenHands as the provider, then <code>minimax-m2.5</code> as your model.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/698dfe1315ef3d8fc660f523_Screenshot%202026-02-12%20at%209.46.50%E2%80%AFAM.png" loading="lazy" alt=""/></div></figure><p>You’ll be able to code with this very capable model entirely for free through the <a href="https://docs.openhands.dev/openhands/usage/cloud/cloud-ui">GUI</a>, <a href="https://docs.openhands.dev/openhands/usage/cli/installation">CLI</a>, <a href="https://docs.openhands.dev/sdk">SDK</a>, or integrations into <a href="https://docs.openhands.dev/openhands/usage/cloud/github-installation">GitHub</a> and <a href="https://docs.openhands.dev/openhands/usage/cloud/slack-installation">Slack</a>.</p><h1>Final Words</h1><p>We’re pretty excited about this moment! OpenHands + MiniMax M2.5 now offer a fully open stack that is quite capable and accessible for software engineering. And this is not to mention the other exciting releases that are coming out from other model providers such as Qwen3-Coder-Next and GLM-5.</p><p>We’ll be continuing testing these out and reporting back to the community, so keep your eyes open for future reports on these as well! If you’d like to follow in real time, feel free to join us on <a href="https://openhands.dev/joinslack">Slack</a> as well, where we discuss developments.</p><p>Happy coding!</p>
