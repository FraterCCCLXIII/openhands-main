<p>Teams are starting to use AI agents for real engineering work, but that usage breaks down quickly at scale. There is no centralized control over what agents can access or how they behave, which makes them difficult to approve for production use. Workflows are fragmented across tools and scripts, with little ability to reuse or standardize how work gets done. Teams also lack visibility into what agents are actually doing. There is no reliable audit trail, no clear understanding of cost, and no way to improve performance over time.</p><p>As a result, most organizations get stuck. Agents show promise, but they are too risky, too opaque, and too inconsistent to scale.</p><h2>Run agents as a system, not one-off tools</h2><p>OpenHands Enterprise provides a fully self-hosted, on-premise system for running AI agents across an organization, with the infrastructure required to control, observe, and scale that work. At the center is the <a href="https://openhands.dev/blog/agent-control-plane">Agent Control Plane</a>, which manages how agents operate across workflows, repositories, and teams. It enforces access policies, tracks usage and cost, and provides a complete record of agent activity.</p><p>Running agents as a system requires more than control. It requires a consistent way to define and execute work across that system.</p><h3>Turn agent usage into repeatable workflows with OpenHands Automations</h3><p>Today, we are excited to share that <a href="https://docs.openhands.dev/openhands/usage/automations/overview#automations-overview">OpenHands Automations</a> is now available in <a href="https://openhands.dev/enterprise">OpenHands Enterprise</a>. Automations are how teams move from one-off agent usage to repeatable, system-driven workflows.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="OpenHands Automations dashboard showing scheduled automations for issue categorization and PR summary" src="/assets/webflow/blog/20260506-openhands-enterprise-agent-control-plane/automations.png" loading="lazy"/></div></figure><p>Instead of running agents manually, teams can define workflows once and run them on a schedule or trigger them based on real events across their systems. These workflows can be reused across repositories and teams, turning what was previously fragmented agent usage into a shared system for execution.</p><p>This is not limited to a single use case. It is a pattern that applies across common engineering workflows. Use cases include:</p><ul role="list"><li><strong>Vulnerability remediation at scale:</strong> Automatically detect, fix, and open PRs for vulnerabilities across your codebase on a schedule.</li><li><strong>Dependency upgrades across repositories:</strong> Trigger updates when new versions are released and apply changes across all affected services.</li><li><strong>PR review and feedback workflows:</strong> Review pull requests automatically with consistent feedback, suggestions, and issue detection.</li><li><strong>Incident response and remediation:</strong> Trigger agents from alerts to investigate issues and propose fixes in real time.</li><li><strong>Large-scale codebase changes:</strong> Apply migrations or refactors across hundreds of repositories with a single workflow.</li></ul><p>All execution runs inside a sandboxed runtime, which isolates agent activity and ensures that work is performed in a controlled environment. This makes it possible to run agents on demand, integrate them into real systems, and scale usage without introducing risk. Run your first <a href="https://docs.openhands.dev/openhands/usage/automations/overview#automations-overview">automation</a> today.</p><h2>Make agent adoption viable at scale</h2><p>This shift is not about incremental productivity. It changes how engineering work gets done at the organizational level.</p><p>For platform, DevOps, and infrastructure leaders responsible for what runs in production, this creates a path to safely operationalize agents. Instead of one-off experiments scattered across teams, agent workflows become defined, repeatable systems that can be deployed, monitored, and improved over time. You increase output without adding headcount by moving repetitive work into systems that run consistently across the organization.</p><p>For security and compliance teams, this introduces the controls required to approve agent usage in production. Access is scoped, activity is auditable, and execution is contained within defined boundaries, making agent usage in production enforceable and accountable.</p><p>For engineering leadership and the business, this creates a more predictable model for execution. Work is no longer fragmented across tools and teams. It becomes measurable, governed, and aligned to outcomes, allowing organizations to scale automation without introducing operational risk.</p><h2>Shift from manual execution to system-driven workflows</h2><p>The biggest change is not what agents can do. It is how developers use them. Instead of building and running isolated automations, teams define workflows once and run them across systems.</p><p>A task like code review or vulnerability remediation no longer needs to be handled manually across repositories. It becomes a repeatable workflow that runs consistently, either on a schedule or in response to events. Developers shift from executing work to defining how it should be done and reviewing the results. Over time, teams refine these workflows, improving performance without starting from scratch.</p><p>The result is a move from fragmented automation to a coordinated system for executing engineering work.</p><h2>The Agent Control Plane</h2><p>Running a single agent is a local problem. Running hundreds across an organization is a coordination problem. The Agent Control Plane is the layer that solves that. It provides centralized control over how agents operate across repositories, teams, and environments, ensuring that automation can scale without losing visibility or control.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img alt="Agent Control Plane architecture showing default policies, guardrails, budgeting, observability, LLM gateway, reporting, plugin marketplace, and integrations" src="/assets/webflow/blog/20260506-openhands-enterprise-agent-control-plane/diagram.png" loading="lazy"/></div></figure><p>At a technical level, it introduces a few core capabilities:</p><ul role="list"><li><strong>Orchestration:</strong> Workflows are no longer tied to individual sessions. They can be defined once and executed across many repositories in parallel, with built-in scheduling, retries, and state management.</li><li><strong>Organization plugins and skills:</strong> With an available Plugin Marketplace, agent builders can publish plugins and skills that developers in the organization can use in their own workflows.</li><li><strong>Sandboxed execution:</strong> All agent activity runs inside isolated environments. Code execution, file access, and external calls are contained and observable. This reduces risk and creates a consistent execution model.</li><li><strong>Observability and auditability:</strong> Every conversation is logged and tied to a user. You can trace what happened, when it happened, and why. This is critical for both debugging and compliance.</li><li><strong>Cost attribution:</strong> Usage is tracked at the organization, user, and conversation level, giving teams clear visibility into how LLM costs are spent. Budgets can also be enforced at the organization and user level.</li></ul><p>As organizations begin to scale automation, the next challenge is not just control, but optimization.</p><p>To support this, OpenHands introduced the <a href="https://index.openhands.dev/">OpenHands Index</a>, a benchmark and leaderboard that evaluates how AI agents perform across real software engineering tasks. It provides a standardized way to compare models based on ability, cost, and runtime, helping teams choose the right model for each workflow and continuously improve how agents operate.</p><p>Together, these capabilities turn agent usage from something ad hoc into a system that can be managed, measured, and improved over time. Teams can scale automation while maintaining control, security, and accountability.</p><h2>How to get started</h2><p>You do not need to adopt everything at once. Most teams start small and expand over time.</p><ol role="list"><li><strong>Start with a single workflow:</strong> Pick a narrow, repeatable task such as dependency updates or PR reviews and run it with an agent.</li><li><strong>Move into a controlled environment:</strong> Run that workflow inside a sandboxed runtime with defined permissions. Start introducing boundaries around what the agent can access.</li><li><strong>Define the workflow in code:</strong> Use the SDK to make the workflow repeatable across repositories.</li><li><strong>Connect it to real systems:</strong> Trigger the workflow based on events from systems like GitHub or your issue tracker.</li><li><strong>Scale with the control plane:</strong> Manage execution across teams, enforce policies, and track cost and behavior as usage grows.</li></ol><p>Ready to get started? <a href="https://app.all-hands.dev/">Sign up and try OpenHands live</a> or take a look at our <a href="https://docs.openhands.dev/overview/quickstart">open source</a> for running and experimenting with OpenHands locally. Download it, try it, break it, build with it. And when it is time to scale, <a href="https://openhands.dev/contact">we are here to help</a>.</p><h2>About OpenHands</h2><p>OpenHands is an open-source platform for building and running autonomous AI coding agents, with the control layer needed to run them safely at scale.
