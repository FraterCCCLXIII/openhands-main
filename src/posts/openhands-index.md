<h1>Introducing The OpenHands Index</h1><p>AI agents are now accelerating all aspects of software engineering, from fixing issues, to building new frontend apps, debugging software, and more. These agents are powered by language models, which each have different strengths, weaknesses, and costs of operation. However, up until this point there was no rigorous way to know the ability of various language models across all these different aspects of software engineering.</p><p>Today, we are happy to introduce the <a href="https://huggingface.co/spaces/OpenHands/openhands-index">OpenHands Index</a>, the first broad-coverage, continually updated leaderboard that evaluates a variety of language models over a broad variety of software engineering tasks. We evaluate them with respect to ability, cost, and run time across 5 different tasks: issue resolution, greenfield apps, frontend development, software testing, and information gathering. This gives coding agent users the ability to <strong>choose the best model based on their priorities and use cases</strong>. Read on for more!</p><h2>Why Build This?</h2><p>When using AI agents for software engineering, we have two choices: <strong>which coding agent</strong> to use, and <strong>which language model to use</strong> to power that agent.</p><p>For some popular coding agents such as Claude Code by Anthropic and the Codex CLI by OpenAI, the answer about what language model to use is easy. These agents are created by the language modeling companies themselves, and because of this they are <strong>language model specific</strong> — they basically only support one language model family well.</p><p>On the other hand, other coding agents like OpenHands and OpenCode are <strong>language model agnostic</strong>, they can be used with a wide variety of models. This has a large number of benefits — <strong>some language models are better at some things than others</strong>, so having the ability to switch between the models allows you to, for example, switch to one model for architectural planning, another model for actual implementation, and yet another for code review and testing. But this is a double-edged sword! Unless you’re a language model connoisseur, it makes it more <strong>difficult to decide which model to use</strong> in the first place.</p><p>Current solutions for benchmarking typically are limited in scope. The popular <a href="https://www.swebench.com/">SWE-Bench Leaderboard</a>, for instance, considers only issue resolution on open-source Python repositories. But there is a lot more to software engineering than this — that is what the OpenHands index tests.</p><h2>The Benchmark</h2><p>When setting up a benchmark for language models in agentic tasks, there are two decisions to make. The first is what <strong>agent framework</strong> to use, and the second is <strong>which dataset(s)</strong> to include.</p><p>For our agent framework, as the benchmark name suggests, we use the <a href="https://github.com/OpenHands/software-agent-sdk"><strong>OpenHands Software Agent SDK</strong></a>, a production grade agent framework that is both used widely in real-world applications and research.</p><p>For datasets, we took a systematic approach. First, we looked at statistics from production traffic to the <a href="https://app.all-hands.dev/">OpenHands Cloud</a>, found several important areas where users tend to rely on coding agents to perform work. Within each area, we found a representative dataset that we could evaluate on:</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae07bc532b1bc0897f546_openhands-index-tasks.png" loading="lazy" alt=""/></div></figure><ul role="list"><li><strong>Issue Resolution:</strong> One major class of coding tasks is fixing issues, such as those posted on GitHub. For this, we use the common <a href="https://openai.com/index/introducing-swe-bench-verified/">SWE-Bench-Verified</a> benchmark.</li><li><strong>Greenfield Development:</strong> This includes creating applications from scratch over long horizons. We test this using the <a href="https://commit-0.github.io/">commit0</a> benchmark.</li><li><strong>Frontend Development:</strong> A common use case for “vibe coding”, this involves making improvements to frontend apps. We use a new “verified” version of the <a href="https://www.swebench.com/multimodal.html">SWE-Bench Multimodal</a> benchmark, filtered to improve accuracy.</li><li><strong>Software Testing:</strong> When debugging software, a first essential step is to identify the bug and generate tests that can reproduce the error. For this we use <a href="https://swtbench.com/?results=verified">SWT-Bench</a>.</li><li><strong>Information Gathering:</strong> When performing software development, it is essential to gather information about APIs or other implementation details. We measure this using the <a href="https://huggingface.co/spaces/gaia-benchmark/leaderboard">GAIA benchmark</a>.</li></ul><p>All of these are implemented and open sourced in the <a href="https://github.com/OpenHands/benchmarks">OpenHands/benchmarks</a> repo.</p><h2>The Takeaways</h2><p>Together with our release, we have benchmarked 9 language models from top providers such as Anthropic, OpenAI, Google, Deepseek, and Alibaba Qwen. Here are some takeaways for users of language models. Below we’ve plotted the models, and you can see more results on the <a href="https://index.openhands.dev">OpenHands Index site</a>.</p><h3>Claude 4.5 Opus: The Overall Winner</h3><p>Claude 4.5 Opus, the flagship model by Anthropic, has been a favorite for users of coding agents of all stripes. It was released in Nov 24, 2025, and as exemplified by <a href="https://x.com/karpathy/status/2004607146781278521?s=20">AI expert Andrej Karpathy’s post</a>, many have felt that it’s qualitatively much better than previous models.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae0a36d2fed13e75e92c2_andrej-karpathy-post.png" loading="lazy" alt=""/></div></figure><p>If you look at just the traditional benchmark of <a href="https://index.openhands.dev/issue-resolution">SWE-Bench Issue Resolution</a>, the story is not very clear, there is only a small gap when comparing Opus to other models such as OpenAI’s gpt-5.2-codex, Google’s Gemini Flash, or DeepSeek v3.2 Reasoner.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae0c834339b29eb29fa3e_openhands-index-swebench.png" loading="lazy" alt=""/></div></figure><p>But when compared across the full OpenHands Index, the difference becomes clear, Claude Opus and OpenAI gpt-5.2-codex are clear leaders, while the others fall significantly behind.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae008c16d7711317c4b54_openhands-index-headline.png" loading="lazy" alt=""/></div></figure><p>In particular, it was the top system in resolving issues, frontend development, and writing unit tests to debug existing issues, and second in the other two categories, demonstrating strong across-the-board performance.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae111311a460952d03c84_openhands-index-systems-by-category.png" loading="lazy" alt=""/></div></figure><h3>GPT 5.2 Codex: A Powerful Tool for Long-term Tasks</h3><p>While Claude 4.5 Opus excels overall, GPT 5.2 Codex, OpenAI’s newly released model for coding tasks, was also quite powerful. It was a close second to Claude Opus overall at a reasonable price point, and it particularly excelled at <a href="https://index.openhands.dev/greenfield">long-horizon Greenfield development tasks</a>, where it worked twice as long as Claude Opus, but achieved a significantly higher success rate.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae13eca7b9e6fd60f1cc8_openhands-index-greenfield.png" loading="lazy" alt=""/></div></figure><p>This is also reflects anecdotes from the community. For instance, <a href="https://x.com/mntruell/status/2011562190286045552">Cursor CEO Michael Truell posted</a> an anecdote that the model ran for a week and was able to build a somewhat functional web browser.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae35a568acc78c75114c4_openhands-index-cursor-browser-post.png" loading="lazy" alt=""/></div></figure><p>This indicates that GPT 5.2 Codex is a strong companion if you want to perform these sorts of these long-running tasks.</p><h3>Affordable but Powerful: Gemini Flash, Deepseek 3.2 Reasoner</h3><p>However, two characteristics of Claude Opus and GPT 5.2 is that they are somewhat pricy. Looking at the cost-accuracy curve, there were two other models that stand out.</p><ul role="list"><li><strong>Google Gemini</strong> comes in two editions, the larger <a href="https://deepmind.google/models/gemini/pro/">Gemini 3 Pro</a> and the smaller <a href="https://blog.google/products-and-platforms/products/gemini/gemini-3-flash/">Gemini 3 Flash</a>. Interestingly, Gemini 3 Flash actually exceeded the accuracy of Gemini 3 Pro on average. It was particularly good at standard code-based tasks such as issue resolution, greenfield development, and testing, but struggled on frontend development. Overall, Google’s models are strong contenders, but did not quite rise to the level of those from Anthropic or OpenAI.</li><li><strong>Deepseek</strong>, the Chinese company which made a name for itself in creating the open-weight DeepSeek R1, a serious competitor to closed models, continues to put out strong models. Its latest <a href="https://api-docs.deepseek.com/news/news251201">DeepSeek-v3.2</a> was the strongest open model. It particularly shined at long-horizon greenfield development tasks.</li></ul><h3>Task Resolution Speed</h3><p>In addition to cost, the efficiency with which tasks can be resolved is another important point — more speedy resolution means that users can form a tighter feedback loop with the agents.</p><p>Interestingly, and somewhat surprisingly, Claude 4.5 Opus, despite being a relatively large model (which means that it may take more compute generating each token), finished tasks much more quickly than others. Our qualitative experience using Opus backs this up however — it is particularly good at using parallel tool calls to quickly zero in on the task and solving it decisively.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae17739e74d3ce38c82c5_openhands-index-speed.png" loading="lazy" alt=""/></div></figure><p>Another notable finding is that the closed models were generally quite a bit faster than the open models at solving tasks as well. This may reflect investments in efficient proprietary inference algorithms of model architectures that have not propagated back to open models.</p><figure class="w-richtext-align-center w-richtext-figure-type-image"><div><img src="https://cdn.prod.website-files.com/68ff4058b35616cdd47d5b59/697ae1939a15f8e2a44f4be5_openhands-index-speed-openness.png" loading="lazy" alt=""/></div></figure><p>That being said, the open models were generally evaluated using inference providers using standard GPU hardware, and not specialized hardware such as <a href="https://groq.com/">Groq</a> or <a href="https://www.cerebras.ai/">Cerebras</a>.</p><h2>What’s Next?</h2><p>This is just a taste of some of the interesting takeaways from the benchmark, so we’d encourage you to dive in to the data yourself on the <a href="https://index.openhands.dev/home">OpenHands Index</a> site!</p><p>Going forward, in the near future, we’re planning on adding more models of interest, both ones that have been released already, and new ones as they come out. In the somewhat farther future, we’re planning on refreshing the index with new benchmarks covering important aspects of software engineering.</p><p>Want to explore more?
