<p>Autonomous agents for software development are already contributing to a <a href="/blog/8-use-cases-for-generalist-software-development-agents">wide range of software development tasks</a>.
But up to this point, strong coding agents have relied on proprietary models, which means that even if you use an open-source agent like <a href="https://github.com/OpenHands/OpenHands">OpenHands</a>, you are still reliant on API calls to an external service.</p>
<p>Today, we are excited to introduce OpenHands LM, a new open coding model that:</p>
<ul>
<li>Is open and <a href="https://huggingface.co/all-hands/openhands-lm-32b-v0.1">available on Hugging Face</a>, so you can download it and run it locally</li>
<li>Is a reasonable size, 32B, so it can be run locally on hardware such as a single 3090 GPU</li>
<li>Achieves strong performance on software engineering tasks, including 37.2% resolve rate on SWE-Bench Verified</li>
</ul>
<p>Read below for more details and our future plans!</p>
<h2 id="what-is-openhands-lm">What is OpenHands LM?</h2>
<p>OpenHands LM is built on the foundation of <a href="https://huggingface.co/Qwen/Qwen2.5-Coder-32B-Instruct">Qwen Coder 2.5 Instruct 32B</a>, leveraging its powerful base capabilities for coding tasks. What sets OpenHands LM apart is our specialized fine-tuning process:</p>
<ul>
<li>We used training data generated by OpenHands itself on a diverse set of open-source repositories</li>
<li>Specifically, we use an RL-based framework <a href="https://arxiv.org/abs/2412.21139">SWE-Gym</a> and <a href="/blog/evaluation-of-llms-as-coding-agents-on-swe-bench-at-30x-speed">All Hands's scalable training infrastructure</a>, allowing us to set up a training environment, generate training data using an existing agent, and then fine-tune the model on examples that were resolved successfully</li>
<li>It features a 128K token context window, ideal for handling large codebases and long-horizon software engineering tasks</li>
</ul>
<h2 id="matching-sota-open-models-20x-larger">Matching SOTA Open Models 20x Larger</h2>
<p>We evaluated OpenHands LM using our latest <a href="https://github.com/OpenHands/OpenHands/tree/main/evaluation/benchmarks/swe_bench#run-inference-rollout-on-swe-bench-instances-generate-patch-from-problem-statement">iterative evaluation protocol</a> on the <a href="https://www.swebench.com/#verified">SWE-Bench Verified benchmark</a>.</p>
<p>The results are impressive:</p>
<ul>
<li><strong>37.2% verified resolve rate</strong> on SWE-Bench Verified</li>
<li>Performance comparable to models with <strong>20x more parameters</strong>, including Deepseek V3 0324 (38.8%) with 671B parameters</li>
</ul>
<p>Here's how OpenHands LM compares to other leading open-source models:</p>

<h2 id="getting-started-how-to-use-openhands-lm-today">Getting Started: How to Use OpenHands LM Today</h2>
<p>You can start using OpenHands LM immediately through these channels:</p>
<ol>
<li>
<p><strong>Download the model from Hugging Face</strong>
   The model is available on <a href="https://huggingface.co/all-hands/openhands-lm-32b-v0.1">Hugging Face</a> and can be downloaded directly from there.</p>
</li>
<li>
<p><strong>Create an OpenAI-compatible endpoint with a model serving framework</strong>
   For optimal performance, it is recommended to serve this model with a GPU using <a href="https://github.com/sgl-project/sglang">SGLang</a> or <a href="https://github.com/vllm-project/vllm">vLLM</a>.</p>
</li>
<li>
<p><strong>Point your OpenHands agent to the new model</strong>
   Download <a href="https://github.com/OpenHands/OpenHands">OpenHands</a> and follow the instructions for <a href="https://docs.all-hands.dev/modules/usage/llms/local-llms">using local models</a>.</p>
</li>
</ol>
<h2 id="the-road-ahead-our-development-plans">The Road Ahead: Our Development Plans</h2>
<p>This initial release marks just the beginning of our journey. We will continue enhancing OpenHands LM based on community feedback and ongoing research initiatives.</p>
<p>In particular, it should be noted that the model is still a research preview, and (1) may be best suited for tasks regarding solving github issues and perform less well on more varied software engineering tasks, (2) may sometimes generate repetitive steps, and (3) is somewhat sensitive to quantization, and may not function at full performance at lower quantization levels.
Our next releases will focus on addressing these limitations.</p>
<p>We're also developing more compact versions of the model (including a 7B parameter variant) to support users with limited computational resources. These smaller models will preserve OpenHands LM's core strengths while dramatically reducing hardware requirements.</p>
<p>We encourage you to experiment with OpenHands LM, share your experiences, and participate in its evolution. Together, we can create better tools for tomorrow's software development landscape.</p>
